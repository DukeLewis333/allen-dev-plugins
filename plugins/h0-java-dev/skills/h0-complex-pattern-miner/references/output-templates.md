## Skill Definition Template

Use this template when the identified pattern is primarily a reusable design pattern or reference knowledge that Claude should understand and apply.

```markdown
---
name: [kebab-case-pattern-name]
description: >
  [One paragraph explaining what this pattern does and when to use it.
  Include trigger phrases that a user might say when they need this pattern.
  Be specific enough to differentiate from similar patterns.]
---

# [Pattern Name]

## Problem Statement

[Describe the business or technical problem this pattern solves in 2-3 sentences.
Explain WHY existing approaches are insufficient.]

## Architecture

[ASCII architecture diagram showing class relationships]

## Implementation Guide

### Step 1: [First implementation step]

[Detailed instructions with code examples]

### Step 2: [Second implementation step]

[Continue with concrete steps]

## Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| [Decision 1] | [Why this choice was made] |

## Pitfalls to Avoid

- **[Pitfall 1]**: [Description and how to avoid]

## When NOT to Use This Pattern

[Describe scenarios where this pattern would be over-engineering or inappropriate.]

## Checklist

- [ ] [Verification step 1]
- [ ] [Verification step 2]
```

## Decision Guide: Skill vs Agent

| Factor | Skill | Agent |
|--------|-------|-------|
| Primary output | Knowledge, pattern documentation | Executable workflow |
| Trigger | "How do I implement X?" | "Run the X process" |
| User interaction | Reference material, templates | Automated steps with checkpoints |
| Reusability | Pattern can be adapted to new contexts | Workflow is repeatable as-is |
| Examples | Template Method Pipeline, Scoring Engine | Order Import, Payment Matching |

**Rule of thumb**: If a user would say "show me how to build X", it is a Skill. If they would say "do X for me", it is an Agent.
